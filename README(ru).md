# docx-chunking

[![smoke](https://github.com/kukhta-nsu/docx_chunking/actions/workflows/ci.yml/badge.svg)](https://github.com/kukhta-nsu/docx_chunking/actions/workflows/ci.yml)

[English version](README.md)

## Что это

Инструмент чанкинга: разбирает Word документы формата `.docx` в дерево нумерованных разделов и режет его
на чанки для поиска. Таблицы разбираются полностью — с объединёнными ячейками
и многоуровневыми шапками.

На выходе -- чанки, обогащенные метаданными. Сохраняются одним файлом в проекте chunks/chunks.jsonl

## Как пользоваться

**1. Скачайте проект.**

```bash
git clone https://github.com/kukhta-nsu/docx_chunking
cd docx_chunking
```

**2. Поставьте инструмент.** Нужен Python 3.10 или новее:

```bash
pip install -e .
```

**3. Положите свои `.docx` в `documents/`.** Папка уже есть, внутри записка.

**4. Запустите.**

```bash
docx-chunking chunk          # documents/*.docx  ->  chunks/chunks.jsonl
```

## Что на выходе

`chunks/chunks.jsonl` — одна строка JSON на чанк. Это настоящий чанк,
полученный из небольшого документа с двухуровневой шапкой таблицы:

```json
{
  "chunk_id": "регламент.docx#1-0",
  "file": "регламент.docx",
  "doc_code": "",
  "doc_title": "регламент",
  "section_num": "1",
  "section_all": "1,2,5,5.1",
  "section_title": "ЦЕЛЬ",
  "section_path": "ЦЕЛЬ",
  "kind": "mixed",
  "part": 0,
  "wide_row": false,
  "head": "регламент\n1 ЦЕЛЬ",
  "body": "Определить порядок работы с документами.\n\nВсе подразделения организации.\n\n№: 1; Хранение / место: ООиОТ; Хранение / срок: 3 года\n№: 2; Хранение / место: Архив; Хранение / срок: постоянно",
  "n_tokens": 68,
  "n_chars": 204,
  "text": "регламент\n1 ЦЕЛЬ\n\nОпределить порядок работы с документами. …"
}
```

| Поле | Что значит |
|---|---|
| `chunk_id` | `<код документа или имя файла>#<раздел>-<часть>` |
| `file` | Имя файла, из которого взят чанк |
| `doc_code` | Код документа, если задан `--code-pattern`; иначе пусто |
| `doc_title` | Имя файла без расширения |
| `section_num` | Номер первого раздела чанка |
| `section_all` | Все номера разделов в чанке после склейки — `1,2,5,5.1` |
| `section_title` | Заголовок первого раздела; пусто, если структуры в документе нет |
| `section_path` | Путь раздела от корня: `ОПИСАНИЕ РАБОТЫ / ХРАНЕНИЕ`; пусто без структуры |
| `kind` | `text`, `table` или `mixed`; годится как фильтр поиска |
| `part` | Номер чанка внутри группы разделов |
| `wide_row` | Внутри есть запись таблицы длиннее бюджета, и чанк сознательно крупнее нормы |
| `head` | Шапка: название документа и путь раздела. Контекст для вектора и готовая ссылка для ответа |
| `body` | Само содержимое без шапки |
| `n_tokens` | Размер в токенах по тому счётчику, который вы передали |
| `n_chars` | Размер в знаках |
| `text` | То, что идёт в эмбеддинг: шапка, пустая строка, содержимое |

`-f csv` и `-f parquet` пишут те же поля. Из Python `chunk_documents()`
возвращает объекты `Chunk`, а `to_dict()` даёт тот же плоский словарь.

## Как работает

**1. Разбор.** Структура ищется тремя способами по порядку, первый
сработавший выигрывает:

| Способ | Когда применяется |
|---|---|
| нумерация разделов | есть согласованная нумерация — предпочтительный путь |
| стили заголовков Word (`w:pStyle`, `w:outlineLvl`) | нумерации нет; номера разделов синтезируются из уровней стилей |
| весь документ одним разделом | нет ни того, ни другого; текст режется по предложениям, таблицы остаются целыми |

Задать явно — `--headings numbering|styles|flat` или `headings=` в `parse()`.

**2. Таблицы.** Объединения разворачиваются: `gridSpan` дублирует значение
вправо, `vMerge:continue` наследует сверху, шапка из двух-трёх строк
склеивается в «Хранение / место». 

**3. Нарезка.** Единица — раздел, а не окно по тексту: у раздела есть номер,
заголовок и путь, на него можно сослаться, и он почти всегда отвечает на один
вопрос целиком. 

Действуют три правила:

| Правило | Почему |
|---|---|
| Мелкие родственные разделы склеиваются | Раздел из двух строк отдельным чанком бесполезен. Склеиваются соседи по одному родителю и родитель с ребёнком, пока сумма влезает в бюджет |
| Переполненный раздел режется по предложениям | Требование, разрезанное посреди фразы, перестаёт быть ответом |
| Запись таблицы не рвётся посреди пары | Обрезок теряет привязку значений к именам колонок |

```python
cfg = dc.ChunkConfig(
    target_tokens=600,          # бюджет чанка вместе с шапкой
    hard_limit=1000,            # выше этого чанк считается проблемой, кроме wide_row
    merge_below=60,             # разделы короче этого склеиваются
    overlap=80,                 # перехлёст при нарезке сплошного текста
    head_template="{doc_title}\n{section_num} {section_path}",
    split_wide_records=False,   # True: ни один чанк не выходит за бюджет
)
chunks = dc.chunk_documents(docs, config=cfg)
```

**4. Контроли.** Разбор `.docx` не падает с ошибкой — он молча теряет
содержимое, и результат при этом выглядит нормально. Поэтому проверки встроены
в инструмент:

* `validate()` работает на каждом `chunk`: нет чанков сверх предела без
  пометки, нет разделов с содержимым вне чанков, ни одна запись таблицы не
  разорвана.
* `coverage()` в команде `check` считает узлы `w:t` в файле и узлы, до которых
  доходит обход. Расхождение означает, что разбор не увидел части вашего
  документа, — единственная поломка, невидимая по результату.

## Для каких файлов

**Только `.docx`.** Бинарный `.doc` до 2007 года без внешнего
конвертера не прочитать; такие файлы конвертируйте заранее Word'ом или
LibreOffice. `parse()` на `.doc` отказывается с внятным сообщением, а `chunk`
по каталогу печатает в stderr каждый найденный `.doc` — вместо того чтобы тихо
оставить документ за пределами индекса. Файлы блокировок (открытые файлы) Word (`~$имя.docx`)
пропускаются.

**Нумерация разделов желательна, но не обязательна.** Без неё идут стили
заголовков, без них — весь документ одним разделом: чанки будут, но
`section_title` и `section_path` окажутся пустыми, и сослаться в ответе будет
не на что. Какой способ сработал на каждом файле, печатают `sections` и `chunk`.

**Нужен извлекаемый текст.** Картинок и OCR здесь нет: `.docx`, внутри
которого одно изображение, даёт ноль разделов и ноль чанков. Такие файлы
названы отдельной строкой.

**Таблица из одной строки записей не даёт:** её единственная строка читается
как шапка. Word использует такие таблицы как рамку, и подпись внутри
отбрасывается осознанно.

Прежде чем доверять корпусу, прогоните по своей папке `docx-chunking check` —
это самый быстрый способ узнать, касаются ли эти ограничения ваших документов.
